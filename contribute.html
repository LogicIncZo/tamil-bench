Contribute to Tamil Bench
தமிழ் பெஞ்சைக்கு பங்களியுங்கள்

Tamil Bench runs open-weight and commercial language models through the same three Tamil exams, and publishes every score with the raw answer sheet behind it. The runs are paid for out of pocket, and this page shows exactly what they cost.

Money is only one of three ways in, and it is the least demanding. Anyone can help, none of them require you to run a single command:

  • Contribute money — every rupee pays for API calls that put new models on the board. Free and :free endpoints are run at zero cost either way.
  • Contribute code — new tasks, better scoring, Tamil transliteration, a dataset loader, a fix for a failing endpoint. The runner is MIT-licensed and small enough to read in an afternoon.
  • Add a new test — the highest-value contribution there is. See the section below for exactly what a new task has to satisfy before it can appear on the board.

A further 24 paid-model sheets covering 3,024 API calls record no charge at all; they were certainly billed, but the sheets do not say by how much, so this figure is a floor, not a closed total. 14 free-tier :free sheets are excluded because they genuinely cost nothing.

Contribute code
கோடு பங்களிப்பு

The whole benchmark is three Python scripts and a folder of answer sheets, MIT licensed. CONTRIBUTING.md is the full guide; this is the short version of what is actually useful.

  • Add a task runner. Each test is one run_<task>() function in bench.py plus a subcommand in main(). This is the main way in.
  • Fix or extend scoring. IndicQA uses exact match and token F1; MILU and IndicXNLI use accuracy over valid rows. A better Tamil-aware normaliser or a confidence interval that reflects the real sampling is a genuine improvement.
  • Handle the awkward cases. Models that answer in Tamil script, in English, in transliteration, or in a mix of all three. A model that fails on format rather than knowledge is a measurement bug, and the fix belongs here.
  • Report a broken run. A dead endpoint, a sheet with fewer rows than expected, a score that looks wrong. Open an issue — no run needed to do this.

Small, reviewable pull requests are easier to land than large ones. If you are unsure whether something is wanted, open the issue first — that costs you a paragraph and saves you a wasted afternoon.

Add a new test
புதிய சோதனை சேர்க்கவும்

This is the contribution with the most leverage: every test added widens what the board can detect. A task qualifies if it is Tamil-specific, has gold labels that are not guessable from the prompt alone, and is not already covered by MILU, IndicQA or IndicXNLI.

  1. Propose it first. Open a new-test issue with the dataset source, licence, language, size, and what a good score means. Datasets that cannot be redistributed belong in data/, which is gitignored — do not commit a copy.
  2. Write the runner. A run_<task>() function in bench.py that samples with SEED = 42, calls the model at temperature 0, and writes results/<task>_<org>_<model-slug>_n<N>.jsonl (/ becomes _ in the model id). Register the subcommand in main().
  3. Gate it. Add a FULL_MIN entry in build_site.py so a smoke-test sheet can never reach the leaderboard. MILU needs 150 rows, IndicQA 90, IndicXNLI 150; pick a floor at least as large as your real task and say why in the PR.
  4. Label it. Add entries to TASK_LABELS (English) and TASK_LABELS_TA (Tamil), and register the page in generate_test_pages() so it gets its own sortable scoreboard.
  5. Show it works. Run at least two models end to end and commit the two sheets. Scores computed from sheets nobody can re-derive are not evidence.

Three rules are not negotiable, because breaking any of them makes the board quietly wrong rather than obviously broken: sampling stays at seed 42 so models stay comparable; failed API calls are never scored as 0% — they are counted and reported as n_errors; and result sheets are append-only evidence, never edited to fix a number.

Request a run for any model
ஏதேனும் மாதிரிக்கான ஓட்டைக் கோரவும்

Name any OpenRouter model id (or a free/open endpoint you want compared) and which exams to run. Runs cost roughly a few dollars each for frontier models and nothing for :free endpoints; a request does not commit you to anything. If nobody funds it, the run simply goes to the back of the queue.

Where the money goes
பணம் எங்கே செல்கிறது


    

  • API calls. Every paid run is metered through OpenRouter and
each answer sheet stores its own charge, so the totals above are auditable line
by line rather than estimated.
    • 

  • Free endpoints stay free. :free routes and
open models are run on the free tier; they expand the board at zero cost.
    • 

  • Open source. The runner, the scoring, and every result
sheet live in https://github.com/LogicIncZo/tamil-bench under an open licence.
Contributions buy runs and compute, not secrecy.
    • 

  • Code counts as much as cash. A new test, a scoring fix, or
a corrected sheet is worth exactly as much to this project as a rupee, and
costs you nothing but the work.
